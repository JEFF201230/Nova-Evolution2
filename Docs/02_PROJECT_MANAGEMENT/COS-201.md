# COS-201

## Contexte

Les audits Knowledge ont montre que le VALIDATOR ne distingue pas encore clairement les situations documentaires observees dans le Knowledge Context Engine.

Dans son comportement actuel, le VALIDATOR peut assimiler a des anomalies de meme niveau des objets qui relevent de natures differentes :

- erreur reelle ;
- placeholder ;
- pattern documentaire ;
- archive ;
- legacy ;
- gap ;
- incubation.

Cette absence de distinction degrade la lisibilite des rapports de validation et peut faire baisser artificiellement le taux de conformite documentaire.

## Objectif

Faire evoluer le VALIDATOR afin qu'il produise deux resultats distincts :

- erreurs reelles ;
- etats documentaires.

Le VALIDATOR doit separer ce qui constitue une erreur a corriger de ce qui constitue un etat documentaire normal, reserve, historique ou transitoire.

## Etats documentaires

### Existing

Document, reference ou objet existant, present dans le perimetre attendu et exploitable comme source documentaire active.

### Placeholder

Document ou entree cree pour reserver un emplacement, un identifiant ou une structure, mais ne contenant pas encore de contenu exploitable.

### Reserved

Identifiant, fichier, section ou relation conserve pour un usage futur explicite. Un element reserve n'est pas une erreur tant que son statut est documente.

### Pattern

Reference volontairement generique utilisee comme motif documentaire, par exemple un chemin de type `COS-*.md` ou une convention de nommage. Un pattern ne doit pas etre traite comme un fichier manquant.

### Gap

Ecart documentaire connu, identifie et conserve comme point de surveillance. Un gap n'est pas une erreur technique tant qu'il est declare comme tel.

### Legacy

Document, chemin, decision ou comportement historique conserve pour memoire, comparaison ou migration. Un element legacy peut ne plus appartenir au flux actif.

### Archive

Document ou reference conserve hors flux actif pour historique, audit ou tracabilite. Une archive ne doit pas etre exigee comme source active.

### Incubation

Document, dossier ou idee en phase exploratoire, non encore integre au socle documentaire officiel. Un element en incubation est suivi separement des erreurs de conformite.

## Erreurs

### Missing

Reference vers un fichier, document ou identifiant attendu comme existant, mais absent du perimetre reel.

### Broken Link

Lien Markdown dont la cible fichier ou dossier n'existe pas dans l'etat courant du depot.

### Invalid Anchor

Lien Markdown pointant vers une ancre absente, invalide ou incoherente avec les titres presents dans le document cible.

### Duplicate Identifier

Identifiant documentaire repete de maniere ambigue dans un meme index ou dans un contexte ou l'unicite est obligatoire.

## Nouveau rapport attendu

Le VALIDATOR devra produire deux sections distinctes.

### Errors

Cette section liste uniquement les erreurs reelles qui exigent correction ou arbitrage.

Elle doit contenir au minimum :

- identifiant ;
- fichier ;
- ligne ou section ;
- type d'erreur ;
- cause.

### Documentation States

Cette section liste les etats documentaires qui ne doivent pas etre assimiles a des erreurs reelles.

Elle doit contenir au minimum :

- identifiant ;
- fichier ;
- ligne ou section ;
- etat documentaire ;
- justification documentaire.

## Impact

Les placeholders, patterns, archives, elements legacy, gaps documentes et contenus en incubation ne doivent plus degrader artificiellement le taux de conformite.

Le taux de conformite doit mesurer les erreurs reelles, tandis que les etats documentaires doivent fournir une lecture qualitative de la maturite du Knowledge Context Engine.

Cette separation permet de certifier plus justement l'etat documentaire courant sans masquer les erreurs effectives.

## Criteres d'acceptation

Le VALIDATOR doit pouvoir distinguer sans ambiguite :

- erreur ;
- etat documentaire.

Un rapport est acceptable si :

- chaque anomalie est classee soit dans `Errors`, soit dans `Documentation States` ;
- aucun placeholder documente n'est compte comme `Missing` ;
- aucun pattern documentaire n'est compte comme lien casse ;
- aucun element archive, legacy, gap ou incubation n'est compte comme erreur tant que son statut est explicite ;
- les `Duplicate Identifier` restent des erreurs lorsque l'unicite documentaire est requise ;
- le taux de conformite est calcule uniquement a partir des erreurs reelles.
