## 1. Mission

Officialize the Kernel Engineering Squad for P3-WS-003 governance and execution support.

The Squad exists to coordinate authorized P3-WS-003 Mission Order execution while preserving PROGRAM-002 certified architecture, Architecture Freeze v1.0, Kernel Baseline v1.0, and all Workstream boundaries.

This charter does not start execution of `MISSION_ORDER_001.md`.

This charter produces no code.

This charter creates no API.

This charter creates no Kernel implementation.

This charter modifies no existing document.

---

## 2. Mandate

The Kernel Engineering Squad is mandated to:

- coordinate P3-WS-003 Mission Order execution when explicitly authorized;
- maintain source authority discipline;
- maintain dependency verification discipline;
- preserve Architecture Freeze v1.0;
- preserve Kernel Baseline v1.0;
- ensure evidence, tests, verification, certification, capitalization, and archive readiness are produced only when authorized by a Mission Order;
- confirm that implementation starts only when the active Mission Order explicitly authorizes implementation.

The Squad is not mandated to change architecture, baselines, doctrines, rules, agents, APIs, workflows, runtime, or Kernel implementation by this charter.

---

## 3. Composition

| Role | Responsibility |
| --- | --- |
| Squad Lead | Coordinate the Squad, receive authorized Mission Orders, maintain scope discipline, track blockers, and confirm handoffs. |
| Chief Architect | Verify Architecture Freeze v1.0, Kernel Baseline v1.0, source authority boundaries, and Change Request requirements. |
| Kernel Engineer | Execute authorized technical or documentary tasks only within the active Mission Order scope. |
| Verification Officer | Verify evidence, tests, acceptance criteria, boundaries, and non-scope compliance. |
| Certification Officer | Certify Mission Order outcomes based on verification evidence and certification criteria. |
| Traceability Officer | Maintain traceability from source authority to execution, evidence, tests, verification, and certification. |
| Configuration & Git Manager | Track authorized files, SHA-256 evidence, configuration state, and absence of unauthorized modifications. |

No additional role is created by this charter.

## 9. Governance Rules

- One Mission Order controls one execution scope.
- No role may bypass the active Mission Order.
- Implementation may occur only when the active Mission Order explicitly authorizes implementation.
- Code may be produced only when the active Mission Order explicitly authorizes code production.
- Architecture Freeze v1.0 and Kernel Baseline v1.0 are preserved unless a separate official Change Request authorizes otherwise.
- Every output must remain traceable to source authority, evidence, tests, verification, and certification.
- Certification must occur before Mission Order closure.
