# NEVIS Implementation Roadmap

## 1. Delivery strategy

La réalisation suit le risque : modèle de contenu et traçabilité d’abord, rendu ensuite, automatisation et échelle enfin. Chaque incrément doit produire un artefact inspectable.

## 2. Phases

| Phase | Scope | Exit evidence |
|---|---|---|
| 0 — Readiness | dépendances, Mission Order, corpus d’essai, baseline visuelle | périmètre et critères approuvés |
| 1 — Canonical model | Decision Frame, claims, metrics, storyline, manifest | schémas et fixtures validés |
| 2 — Design foundation | tokens, masters, layout rules, accessibilité | thème et gabarits multi-format |
| 3 — Component MVP | KPI, bar/line, matrix, heatmap, roadmap, table | composants testés sur données réelles |
| 4 — Document generation | one-page, PDF, PPTX avec notes | rendus sans reprise graphique |
| 5 — Audience variants | CEO, COMEX, banque, investisseur, consultant, NOVA | cohérence inter-versions démontrée |
| 6 — Advanced visuals | radar, bubble, Sankey, waterfall, treemap, benchmark | règles et fallbacks accessibles |
| 7 — Dashboard | vue décision, filtres, drill-down, export | tests responsive et états de données |
| 8 — Quality automation | scoring, blockers, diff visuel, manifest | pipeline de publication bloquant |
| 9 — Certification | corpus complet et tests utilisateurs | evidence pack approuvé |

## 4. MVP boundary

Le MVP couvre : Executive Decision Frame, Executive Summary one-page, deck CEO, deck COMEX, PDF, dashboard décisionnel simple, KPI Cards, graphiques bar/line, heatmap, benchmark, roadmap, sources, notes présentateur et score de readiness.

Les Google Slides natifs, animations avancées, Sankey, treemap, génération à grande échelle et templates spécialisés peuvent suivre après validation du noyau.

## 5. Program risks

| Risk | Control |
|---|---|
| esthétique supérieure à la preuve | gates NSIOS et traçabilité bloquante |
| multiplication de variantes incohérentes | modèle canonique et manifest |
| promesse « niveau cabinet » non mesurable | critères visuels, tests utilisateurs et baselines |
| dépendance aux polices ou formats | fallbacks portables et tests d’export |
| densité excessive | budgets éditoriaux et progressive disclosure |
| graphiques décoratifs ou trompeurs | moteur de sélection et revue humaine |
| dette de composants | contrats, tokens et tests centralisés |
