# NEVIS Templates and Multi-Audience Delivery

## 1. Mandatory template anatomy

Chaque modèle standard comprend :

1. couverture ;
2. sommaire automatique ;
3. Executive Decision Frame ;
4. résumé exécutif ;
5. synthèse visuelle ;
6. storyline avec messages clés ;
7. recommandations, décisions et plan d’action ;
8. risques, confiance et limites ;
9. annexe technique, méthodes, sources et hypothèses.

## 2. Standard templates

| Template | Dominant question | Required emphasis |
|---|---|---|
| Business Plan | le plan est-il finançable et résilient ? | hypothèses, P&L, cash, scénarios, besoins |
| Due Diligence | faut-il poursuivre, conditionner ou abandonner ? | red flags, thèse, risques, valorisation, conditions |
| Market Study | où et comment jouer ? | segmentation, taille, croissance, demande, scénarios |
| Competitive Audit | comment gagner face aux alternatives ? | positionnement, capacités, écarts, mouvements |
| Product Audit | le produit crée-t-il une valeur défendable ? | usage, adoption, différenciation, roadmap |
| UX Audit | quelles frictions détruisent la valeur ? | parcours, preuves, sévérité, gains attendus |
| Pricing Audit | comment capturer la valeur ? | packaging, willingness-to-pay, élasticité, benchmark |
| SaaS Audit | le modèle peut-il croître sainement ? | ARR, MRR, CAC, LTV, churn, NRR, cash |
| Financial Audit | la performance est-elle fiable et durable ? | qualité du revenu, marge, cash, risques |
| Go-to-Market | comment atteindre le marché efficacement ? | ICP, canaux, funnel, economics, plan |
| Roadmap | que livrer, dans quel ordre et sous quelles contraintes ? | jalons, dépendances, ressources, KPI |
| Executive Committee | quelle décision doit être prise maintenant ? | options, verdict, risques, actions |

## 3. Audience profiles

| Audience | Default package | Editorial contract |
|---|---|---|
| CEO | 10 pages maximum | décision, enjeux, options, verdict, actions |
| COMEX | jusqu’à 30 pages | analyse intégrée, arbitrages, owners, KPI |
| Bank | Business Plan | solvabilité, cash, hypothèses, downside, covenants |
| Investor | Investment Deck / Memo | thèse, marché, traction, economics, risques, ask |
| Consultants | Full Report | raisonnement, méthodes, analyses et annexes |
| NOVA | Technical Package | modèle canonique, preuves, règles, logs et manifest |

La longueur est un budget éditorial, pas une cible à remplir. Toute exception est justifiée par matérialité et enregistrée dans le manifest.

## 4. Content transformation rules

- Le verdict et la confiance sont identiques pour toutes les audiences à version égale.
- La profondeur, le vocabulaire, l’ordre et les annexes peuvent varier.
- Un contenu supprimé d’une vue courte reste accessible dans une vue détaillée.
- La version banque ne transforme pas un scénario commercial en engagement financier.
- La version investisseur expose aussi les risques matériels et hypothèses sensibles.
- La version technique conserve l’intégralité des IDs, sources, calculs et exceptions.

## 5. Executive Summary one-page

Structure : problème et pourquoi maintenant ; décision attendue ; verdict ; trois preuves ; trois risques ou conditions ; plan 30/60/90 jours ; KPI ; confiance et sources clés.

## 6. One-page Strategy

Structure : ambition ; terrain de jeu ; avantage recherché ; choix et renoncements ; capacités nécessaires ; roadmap ; KPI ; risques et hypothèses critiques.

## 7. Speaker notes

Les slides générées incluent des notes : objectif de la slide, message à dire, preuve, limite, question probable, réponse sourcée et transition. Les notes ne doivent pas contenir une information critique absente du support ou de ses annexes.

## 8. Delivery formats

| Format | Required properties |
|---|---|
| PowerPoint | objets éditables lorsque possible, thème, masters, notes, lecture statique complète |
| Google Slides | styles transposés, polices disponibles, notes, absence de rupture de mise en page |
| PDF | signets, structure, texte sélectionnable, impression, liens et métadonnées |
| Dashboard | responsive, filtres explicites, états de données, export et drill-down |

## 9. Delivery package

Une livraison complète contient les artefacts demandés, le manifest, la table de traçabilité, le résultat des quality gates, les exceptions acceptées et les références de versions.
