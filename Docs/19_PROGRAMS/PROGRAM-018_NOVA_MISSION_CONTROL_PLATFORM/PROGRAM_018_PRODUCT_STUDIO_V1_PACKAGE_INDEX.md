## 3. Reading and Production Order

1. Product and content designers consume Product Specification and User Journeys.
2. Screen and UI designers consume Screen Specification and Design System.
3. Prototype designers consume Prototype and Figma Handoff.
4. Accessibility, VEEDDA and front-end reviewers consume Validation across every design increment.
5. Certification defines the allowed next phase and boundaries.

No downstream artifact may silently contradict an upstream invariant. A material change requires a recorded product decision and revalidation of affected screens and flows.

## 5. Figma Production Scope

The package requires:

- 32 desktop screen frames and defined variants;
- required tablet, mobile and 320 px reflow frames;
- reusable variables, styles, components and patterns;
- eight primary end-to-end prototype flows plus population and adverse-state routes;
- accessibility annotations and reduced-motion behavior;
- realistic localized content and VEEDDA validation scenarios;
- decision and change logs for material divergences.

## 6. React Boundary

The package prepares React implementation through component mapping, state boundaries and required contracts. It contains no React code and grants no implementation authority.
