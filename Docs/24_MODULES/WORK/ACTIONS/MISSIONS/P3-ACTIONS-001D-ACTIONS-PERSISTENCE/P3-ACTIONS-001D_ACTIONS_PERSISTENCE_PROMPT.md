## CAS AND CONCURRENCY

CAS means Compare-And-Swap.

Every durable Action mutation MUST compare the expected Action revision with the canonical persisted revision.

A Dependency mutation MUST additionally validate the coherent canonical graph revision.

Two concurrent writes MUST NOT silently overwrite each other.

A stale write MUST fail deterministically.

After conflict or persistence failure, canonical state is reread before any new business intention can be evaluated.

Do not invent automatic business compensation.

Do not implement last-write-wins.

## ATOMICITY

The authoritative durable transaction boundary must preserve consistency between all facts generated by one accepted mutation.

Where applicable, commit atomically:

- current Action state;
- Action revision;
- authoritative event(s);
- Result history/current Result semantics;
- Dependency graph mutation;
- graph revision;
- causality receipt;
- provenance.

A failure before completion MUST NOT expose a partially authoritative mutation.

## REPLAY

Provide deterministic replay from the durable canonical source.

Replay MUST:

- preserve event ordering;
- preserve revisions;
- preserve provenance;
- preserve causality;
- preserve Result semantics;
- preserve Dependency semantics;
- reconstruct a state compliant with the certified 001B/001C invariants;
- create no new business fact;
- invoke no external aggregate;
- create no second source of truth.

## RECOVERY

Provide recovery appropriate to the selected persistence mechanism.

Recovery MUST:

- reconstruct canonical durable state after restart/interruption;
- detect malformed or incoherent durable data;
- fail closed when canonical consistency cannot be established;
- preserve append-only history;
- preserve receipts;
- preserve Result uniqueness;
- preserve Dependency acyclicity;
- preserve revisions;
- never invent business compensation;
- never silently discard a conflicting authoritative fact.
