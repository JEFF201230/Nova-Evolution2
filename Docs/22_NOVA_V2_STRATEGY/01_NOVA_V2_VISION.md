# Vision NOVA V2

## Statut du document

STRATÉGIE APPROUVÉE.

## Énoncé de Vision

NOVA v2 marque la transition d’un socle certifié d’Operating System interne vers une plateforme d’exécution d’entreprise commerciale. Il doit rendre crédible la vision de long terme d’un Cognitive Operating System sans faire de l’autonomie complète une condition préalable au premier revenu.

La vision est la suivante :

NOVA devient la couche d’exploitation d’entreprise gouvernée où les humains, les agents IA, les systèmes logiciels, les preuves, les décisions et les produits se coordonnent au travers de missions explicites.

## Vision de Long Terme

NOVA doit, à terme, fonctionner comme un Cognitive Operating System d’entreprise avec cinq responsabilités durables :

- comprendre l’intention stratégique et la convertir en Programs gouvernés ;
- décomposer les Programs en projets, missions, campagnes, preuves, tests et décisions ;
- orchestrer des agents spécialisés et des rôles humains dans des frontières d’autorité strictes ;
- maintenir la mémoire organisationnelle et un graphe de connaissances vivant ;
- améliorer son propre modèle d’exécution grâce à un apprentissage audité et à une évolution approuvée par le Board.

## Principe de Commercialisation

L’objectif numéro un est le time to market. NOVA doit vendre rapidement un produit utile, auditable et de niveau entreprise avant que toutes les capacités cognitives ne soient disponibles.

La première version commerciale doit donc livrer :

- une exécution de mission gouvernée ;
- une visibilité sur l’exécution ;
- un pilotage de Programmes ;
- la supervision des agents ;
- la traçabilité des décisions ;
- le contrôle des coûts IA ;
- des rapports de preuves et de certification ;
- la préparation à l’intégration VEEDDA.

Elle doit différer :

- la création autonome de Programmes ;
- le déploiement autonome de code ;
- l’auto-modification complète de la gouvernance ;
- la monétisation ouverte d’une marketplace ;
- l’exécution large de plugins tiers ;
- les changements de politique d’auto-apprentissage pleinement automatiques.

## NOVA Auto-Évolutif

L’auto-évolution est une capacité par paliers, pas un comportement non borné.

| Palier | Capacité | Gouvernance |
| --- | --- | --- |
| V1 | Socle d’exécution fondé sur la preuve | Approbation du Program Board |
| V1.1 | Mission control industrialisé | Workflows approuvés par l’humain |
| V2.0 | L’IA recommande des Programs, missions, tests et remédiations | Approbation humaine pour l’activation |
| V2.1 | L’IA optimise le séquencement du portefeuille et la capacité | Politique du Board et audit |
| V3.0 | L’IA rédige et maintient des Programs d’évolution | Enveloppe d’autonomie contrôlée par le Board |

NOVA peut suggérer des évolutions avant V3.0. Il ne peut pas activer de manière autonome des travaux à fort impact tant qu’une politique explicite, des garde-fous de risque, de sécurité et de certification ne sont pas en place.

## Autonomous Operating System

La cible Autonomous Operating System est un système capable de coordonner le travail entre Programs sans perdre la responsabilité.

Niveaux d’autonomie principaux :

| Niveau | Description | Moment commercial |
| --- | --- | --- |
| L0 Manuel | L’humain crée et exécute tout le travail ; NOVA enregistre les preuves | socle v1.0.0 |
| L1 Assisté | NOVA guide la création des missions, les transitions d’état, les contrôles et les rapports | v1.1 |
| L2 Délégué | NOVA assigne des agents approuvés et exécute des workflows bornés | v2.0 |
| L3 Autonomie supervisée | NOVA propose des Programs, des plannings, des remédiations et des tests | v2.1 |
| L4 Autonomie par politique | NOVA exécute sous politique des évolutions approuvées à faible risque | v3.0 |
| L5 Autonomie d’entreprise | NOVA optimise en continu l’exécution entreprise avec gestion des exceptions humaines | uniquement à long terme |

La stratégie commerciale cible rapidement le niveau L1, puis L2 après les pilotes entreprise, et L3+ uniquement après la preuve des contrôles de gouvernance.

## Cognitive Operating System

La cible Cognitive Operating System ajoute le raisonnement, la mémoire, le consensus, l’apprentissage et le graphe de connaissances au-dessus du socle d’exécution certifié.

Elle doit inclure :

- Executive AI pour les recommandations de portefeuille ;
- Planner AI pour la décomposition et la planification ;
- Architect AI pour la conformité architecturale ;
- Developer AI pour l’implémentation dans le périmètre de mission ;
- Tester AI pour la validation et les preuves de régression ;
- Reviewer AI pour les contrôles de certification ;
- Learning AI pour les rétrospectives et les demandes d’amélioration ;
- Memory Engine pour le contexte réutilisable ;
- Knowledge Graph pour les relations de dépendance, d’autorité, de preuve et d’impact ;
- Decision Engine pour les politiques, le risque et la priorisation ;
- Reasoning Engine pour l’analyse structurée ;
- Consensus Engine pour l’accord multi-rôle et la détection de conflits.

## Limite de Vision

NOVA ne doit jamais devenir un acteur autonome boîte noire. Il doit rester :

- fondé sur des preuves ;
- borné par une autorité explicite ;
- auditable ;
- réversible autant que possible ;
- piloté par la politique ;
- compréhensible commercialement ;
- déployable en environnement d’entreprise ;
- indépendant de tout fournisseur LLM unique.

## Décision de Vision

NOVA v2 doit poursuivre le leadership du Cognitive Operating System par une séquence commerciale pragmatique : vendre d’abord l’exécution gouvernée, ajouter ensuite la profondeur cognitive, et automatiser l’auto-évolution en dernier.
