# NOVA V2 Scenario Analysis

## Document Status

SCENARIO BASELINE.

## Purpose

This document compares four scenarios using the same operating model logic. It is intended to show which combinations of customer count, pricing, staffing, infrastructure, and investment are needed to reach different revenue outcomes.

## Shared Formula Set

```
ARR = customers x blended ARPA
Services = new logo count x services attach per logo
Infrastructure need = active customers x unit infra cost + model cost + observability overhead
Human need = sales + product + support + security + operations headcount
Investment = cumulative product + go-to-market + enterprise-readiness funding
```

## Scenario Summary

| --- | ---: | ---: | ---: | ---: |
| Customers | 100 | 262 | 360 | 400 |

| ARR | USD 18M | USD 60M | USD 120M | USD 150M |
| MRR | USD 1.5M | USD 5.0M | USD 10.0M | USD 12.5M |
| Services | USD 2.5M | USD 5.5M | USD 8.0M | USD 10.0M |

## Conservative

### Assumptions

- market adoption is slower than planned;
- only the core Mission Ops value is sold;
- enterprise deals are smaller and fewer;
- partner motion remains limited;
- upsell exists but is weak.

### Requirements

| Item | Value |
| --- | ---: |
| Customers | 100 |
| Human needs | 30 to 40 FTE |
| Infrastructure and AI spend | USD 1.5M to 2.5M |
| Investment required | USD 6M to 8M cumulative |

### Interpretation

This scenario is viable if the product is useful but the market is still learning the category. It is not enough to justify a large ecosystem build-out.

## Base Case

### Assumptions

- Mission Ops reaches product-market fit in the target segments;
- retention is strong;
- the sales motion is enterprise-like but repeatable;
- VEEDDA provides a credible vertical proof.

### Requirements

| Item | Value |
| --- | ---: |
| Customers | 262 |
| Human needs | 55 to 70 FTE |
| Infrastructure and AI spend | USD 3.5M to 4.5M |
| Investment required | USD 9M to 12M cumulative |

### Interpretation

This is the target scenario used by the base financial model. It justifies the Mission Ops MVP, then a platform expansion path.

## Ambitious

### Assumptions

- the platform expands beyond Mission Ops into broader enterprise orchestration;
- enterprise deals are larger due to platform modules and private deployment;
- partner-led delivery contributes to scale;
- NRR remains high and churn remains controlled.

### Requirements

| Item | Value |
| --- | ---: |
| Customers | 360 |
| Human needs | 85 to 110 FTE |
| Infrastructure and AI spend | USD 6M to 8.5M |
| Investment required | USD 15M to 20M cumulative |

### Interpretation

This scenario requires stronger enterprise security, private deployment, and a wider product surface. It is credible only if platform expansion starts early and retention is excellent.

## Exceptional

### Assumptions

- NOVA becomes a category leader in governed AI execution;
- marketplace and partner packs contribute meaningfully;
- global enterprise and regulated deployment are both working;
- the product portfolio extends beyond one surface;
- expansion revenue is strong and churn is very low.

### Requirements

| Item | Value |
| --- | ---: |
| Customers | 400 |
| Human needs | 120 to 150 FTE |
| Infrastructure and AI spend | USD 9M to 12.5M |
| Investment required | USD 22M to 30M cumulative |

### Interpretation

This scenario is possible only if NOVA becomes a multi-product platform with strong partner and marketplace leverage. It is not reachable with a single-surface product.

## Scenario Coherence Checks

| Check | Conservative | Base | Ambitious | Exceptional |
| --- | --- | --- | --- | --- |
| Product-market fit needed | Yes | Yes | Yes | Yes |
| Enterprise security needed | Moderate | High | Very high | Very high |
| Private deployment needed | No | Optional | Likely | Yes |
| Marketplace needed | No | Not required | Helpful | Helpful |
| Self-evolution needed | No | No | Later | Later |
| VEEDDA proof needed | Helpful | Helpful | Important | Important |

## Scenario Validation

The scenarios are coherent because the customer count, ARPA, services load, staffing, and infra load scale together. The exceptional case is not just a bigger version of the base case; it requires a different commercial machine with more deployment, partner, and ecosystem leverage.
